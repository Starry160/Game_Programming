# AI Usage Statement

## Purpose

This document explains how AI assistance was used during the development of **Knight Legend**. AI was used as a supporting tool for coding, debugging, documentation polish, and test planning. The project was not fully generated by AI, and the final game design, implementation decisions, Unity integration, testing, and submission preparation were directed and reviewed by the developer.

## Summary

AI assistance was used in a similar way to a programming tutor or pair-programming helper. It helped suggest code structure, identify possible bugs, improve documentation wording, and create lightweight automated EditMode tests. Each suggestion still needed to be checked, adapted, tested, and integrated inside the actual Unity project.

The final submitted project reflects the developer's own contribution through:

- Game concept and feature planning.
- Scene design and Unity object setup.
- Class selection, weapon behavior, level flow, enemy behavior, boss encounter, reward system, and result-screen integration.
- Inspector reference assignment, prefab setup, animation setup, and gameplay tuning inside Unity.
- Manual playtesting with Knight, Mage, and Archer.
- Final review of AI-assisted code before keeping it in the project.
- Documentation, testing records, and repository organization decisions.

## How AI Was Used

I used AI mainly when I needed help thinking through code structure, debugging possible problems, or improving the wording of project documents. For example, AI helped me review scripts related to player stats, damage handling, run statistics, portals, testing records, and cleanup of old serialized fields.

The AI suggestions were not copied blindly. I checked whether they matched my actual Unity scenes, prefabs, Inspector references, and gameplay flow before keeping them. In several cases, I had to test the behavior in Unity, adjust the implementation, or decide that a suggestion was not suitable for my project.

AI was also used to help organize documentation and testing evidence. It helped me write clearer README and testing notes, but I provided the project context and checked that the final documents matched the real game. The manual playthrough results, EditMode test results, and final repository organization were still reviewed and confirmed by me.

In short, AI supported my workflow, but I remained responsible for choosing the design, integrating the code, testing the game, and deciding what stayed in the final submission.

## What Was Not Fully AI-Generated

The project was not created by simply asking AI to make a complete game. AI did not independently design the submitted Unity project, build scenes, assign Inspector references, tune gameplay feel, run manual playthroughs, or decide the final submission scope.

Important parts of the project required direct developer work inside Unity, including:

- Creating and arranging scenes.
- Connecting scripts to GameObjects and prefabs.
- Assigning sprites, animations, audio, colliders, UI elements, and scene references.
- Testing player movement, attacks, enemy behavior, portals, rewards, death, victory, and the final boss.
- Balancing class stats, weapon behavior, enemy encounters, and boss attacks.
- Reviewing every AI-assisted change before keeping it in the repository.

## Quality Control

AI suggestions were treated as drafts, not final answers. The developer checked the project in Unity after changes and kept the parts that worked with the actual game. The final evidence includes:

- Manual regression test records in `TESTING.md`.
- Full playthroughs using Knight, Mage, and Archer.
- Automated EditMode tests under `Assets/Tests/EditMode/Editor/`.
- A successful Unity Test Runner result showing 11 EditMode tests passed, recorded in `doc/evidence/01-test-runner-editmode-pass.png`.
- Final visual evidence for build order, clean Console state, class selection, combat, rewards, final boss behavior, victory, death, and pause flow under `doc/evidence/`.

## Academic Integrity Statement

AI was used as an assistant to support learning and productivity. The developer remained responsible for the game idea, implementation direction, Unity integration, testing, debugging decisions, and final submitted work. The project therefore represents AI-assisted development with substantial original developer contribution.
